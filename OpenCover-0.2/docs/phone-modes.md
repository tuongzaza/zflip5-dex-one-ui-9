# Phone modes while a USB-C desktop is connected

OpenCover 0.2.2 leaves the inner and cover screen density unchanged when starting/stopping the desktop. The old matchInnerDensity workaround (480 -> 160 on the phone) is removed. On the test phone, the inherited override was reset to its default 480 DPI; the cover stays at 340 DPI. Some desktop apps that incorrectly size themselves from the primary display no longer get that workaround.

After a desktop is created, the phone shows two choices. Phone mode returns to ordinary phone use. Touchpad mode shows a relative pad: move one finger to move the shared mouse cursor, tap for primary click, double-tap for double-click, two fingers to scroll, two-finger tap for secondary click, and long-press to drag. The pointer also exists when no physical USB mouse is available. Button holds are released when changing modes, leaving the pad, or locking the phone.

Reopen the choice through **Chế độ điện thoại** in OpenCover's swipe-down Quick Settings or Android Quick Settings, Settings -> Experimental -> Điện thoại / Bàn di chuột, or the app icon with that name. Version 0.2.4 removes the floating phone button; the external taskbar has no mode-switch button. On first use after upgrading, OpenCover inserts the tile at the start of its panel while preserving the order of existing tiles. Subsequent edits/removal are respected. Android's tile is declared as a permission-protected TileService; on the test phone it was added with `cmd statusbar add-tile dev.opencover.globalrotation/dev.opencover.desk.PhoneModeTileService`. Other devices can add it using the system tile editor. Android 14+ uses an immutable explicit activity PendingIntent through startActivityAndCollapse, with unlockAndRun for the lock screen. The tile's subtitle reports the current mode when listening.

The choice is stored. With no connected desktop the pad is unavailable. The activity chooses the active internal display and follows display-state changes; it never opens on the HDMI monitor. Both phone modes leave the desktop running. Old cover idle dimming is inactive in these modes.

The Shizuku helper interface version is 18. Relative input is a bounded, finite, one-way Binder call using the existing desktop mouse injector. It cannot select a different display and respects the existing lock state. Desktop creation no longer forces the phone's keyboard focus onto the desktop merely on start/unlock; actual desktop presses still focus its apps.

Validation: 295 unit tests passed, no failures/errors/skips, including relative movement, first contact, two-finger scroll, finger-count changes and invalid coordinates. On the folded SM-F731N: both mode buttons remain visible below the top navigation/cutout; trackpad moves the external cursor, tap entered 7 then 77 in Calculator, and long-press moved the Calculator window from [348,94,1428,914] to [519,179,1599,999]. Phone mode returned to Home while the desktop remained available; reopening from the desktop taskbar worked in 0.2.2. Version 0.2.3 moves that button to the phone and removes it from the external taskbar. The floating button follows the active internal display and hides while the mode picker is visible or the phone is locked; it is removed when the desktop stops. Both phone screens retained default densities. Physical unfolding, two-finger gestures on hardware, reconnect and reboot remain unverified.

Built and signed with the same local SDK 36 validation profile and user-provided signing key documented in desktop-mirror.md. No signing key is stored in this repository.

0.2.3 validation on the folded phone with HDMI connected: the floating button appeared on display 1, opened the mode picker, and both Phone and Touchpad choices worked. The external desktop (display 386) had no mode-switch button. All 295 unit tests passed. Moving between folded and unfolded screens and lock/reconnect behavior are implemented but not physically retested for this placement change.

0.2.4 validation: 295 unit tests passed. On the folded phone with HDMI connected, the first OpenCover Quick Settings page contained Chế độ điện thoại; tapping it opened the picker on display 1, and both choices worked. The Android tile was added to sysui_qs_tiles and a SystemUI tile click also opened the picker on display 1. No floating phone button remained. The phone was left in ordinary phone mode with OpenCover Quick Settings open. Physical unfolding, reconnect, reboot and locked-tile invocation were not retested. Android API reference: https://developer.android.com/reference/android/service/quicksettings/TileService

## TwinDesk cursor — 0.2.5

Samsung does not draw the system mouse pointer on the OpenCover virtual desktop. TwinDesk's scrcpy input can therefore click on it without moving OpenCover's independent USB/touchpad cursor. DeskService now creates an abstract local socket `opencover_cursor_<displayId>` for cursor drawing only. It accepts Android shell UID 2000, validates the display ID and finite coordinates, and clamps positions to this desktop. Sixteen-byte big-endian frames contain int displayId, float x, float y, int buttonDown. The endpoint cannot inject input, launch apps or select another display. It closes accepted/listening sockets when the desktop is released. Helper version is 19.

The local TwinDesk patch in `/home/tuong/.local/share/zflip-desktop/twindesk-opencover` forwards this socket through ADB and sends the pointer position while its normal scrcpy session handles input on the selected OpenCover display. Cursor forwarding is removed on disconnect and reconnects after failure; no custom cursor is drawn over phone apps. The mode choice remains in Quick Settings.

Validation: Android build and all 295 unit tests passed. Two Node cursor-channel tests and four display-routing tests passed. On folded Z Flip5 with HDMI, the final APK cursor probe moved the physical-monitor overlay to (698,498) for pointer hotspot (700,500), then to (1198,798) for hotspot (1200,800). Frames for a different display and NaN positions left the cursor unchanged. Actual TwinDesk movement frames were observed on-device before removing temporary per-movement logging. TwinDesk was restored to a connected ADB control session targeting OpenCover Desk 390. Physical user confirmation of the final build is tracked in the local setup README.
